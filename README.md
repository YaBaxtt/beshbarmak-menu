# Beshbarmak House

Полноценный сайт ресторана на Django: двуязычное RU/UZ меню, бронирование без регистрации, защищённая страница статуса, Telegram-бот менеджеров, простая панель сотрудников и расширенный Django Admin.

## Быстрый локальный запуск

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
Copy-Item .env.example .env
python manage.py migrate
python manage.py seed_demo
python manage.py createsuperuser
python manage.py runserver
```

Страницы:

- сайт и меню: `http://127.0.0.1:8000/`
- бронирование: `http://127.0.0.1:8000/reservation/`
- панель ресторана: `http://127.0.0.1:8000/staff/`
- Django Admin: `http://127.0.0.1:8000/admin/`

Для macOS/Linux используйте `python3`, а окружение активируйте командой `source .venv/bin/activate`.

## Что сохранено из исходного проекта

Существующие `Category`, `Dish`, `DishImage`, `RestaurantSettings`, RU/UZ-переключение, поиск, фильтры, фотографии, медиа-файлы, `/`, `/admin/` и демонстрационная база сохранены. Бронирования добавлены отдельным Django-приложением `reservations`; меню не переписано.

## Настройка ресторана

Контакты, обложка и тексты остаются в singleton-модели `RestaurantSettings`. В `/staff/settings/` владелец меняет:

- включение онлайн-бронирования;
- минимальное время до визита и глубину календаря;
- длительность брони и интервал слотов;
- минимальное/максимальное количество гостей;
- срок самостоятельной отмены;
- часы каждого дня недели;
- полные и частичные закрытия (ремонт, праздник, частное мероприятие).

Залы и комнаты создаются в `/staff/spaces/` или в Django Admin → «Залы и комнаты». Можно менять русское и узбекское названия/описания, фото, вместимость, тип, порядок, эксклюзивность, возможность бронирования и режим временной недоступности. Удаление из обычной панели мягкое: помещение скрывается, а история сохраняется; через Django Admin неиспользованное помещение можно удалить полностью.

Поводы визита («День рождения», «Семейное мероприятие» и любые новые варианты) находятся в Django Admin → «Поводы бронирования». Их можно добавлять, переименовывать на RU/UZ, сортировать, временно скрывать и удалять. Публичная форма автоматически показывает только активные варианты на выбранном языке.

Акции находятся в Django Admin → «Aksiyalar / акции». Для каждой акции доступны тексты RU/UZ, картинка, ссылка, период показа, порядок и флаг активности. На сайте они собраны в горизонтальную карусель со свайпом, стрелками, точками и спокойной автопрокруткой, поэтому новые баннеры не удлиняют страницу. Это отдельный блок сайта: «популярное» остаётся выбором гостей и не считается акцией.

Язык UZ/RU сохраняется при переходе из меню в бронирование, во всех трёх шагах формы и на странице статуса. На странице бронирования также есть собственный переключатель языка.

## Сотрудники и роли

1. Создайте первого superuser: `python manage.py createsuperuser`.
2. Войдите в `/staff/` этим аккаунтом.
3. Откройте «Сотрудники» → «Добавить сотрудника».
4. Укажите логин, временный пароль, роль и, при необходимости, числовой Telegram ID.

Роли:

- `OWNER` — бронирования, помещения, сотрудники, статистика, настройки и контент;
- `MANAGER` — бронирования, помещения и статистика;
- `CONTENT_MANAGER` — меню и контент через Django Admin без доступа к сотрудникам и бронированиям.

Публичной регистрации сотрудников нет. Отключение `StaffProfile.is_active` немедленно запрещает web-доступ и старые Telegram-кнопки.

## Telegram-бот

Заполните в `.env`:

```dotenv
BOT_TOKEN=123456:telegram-token
PRIMARY_OWNER_TELEGRAM_ID=123456789
SITE_URL=https://your-domain.example
```

`PRIMARY_OWNER_TELEGRAM_ID` автоматически создаёт первого `OWNER` при его первом обращении к боту. Владелец добавляет и отключает администраторов прямо в Telegram через «Administratorlar»; те же сотрудники доступны в web-панели. Менять `.env` для каждого сотрудника не нужно. Уведомления получают только активные `OWNER`/`MANAGER` с включённым флагом Telegram. Если профиль владельца затем отключить в панели, `.env` не обойдёт эту блокировку.

Запуск отдельным процессом:

```powershell
python -m telegram_bot
```

Бот и сайт используют одну базу и один `ReservationService`. Интерфейс бота — на узбекской латинице. Менеджер видит имя и телефон гостя, может подтвердить заявку, предложить другое время, отклонить с причиной, открыть списки, просмотры сайта и статистику броней. Новые жалобы сразу приходят активным владельцам и менеджерам в Telegram и остаются в разделе «Shikoyatlar». Новый отзыв также приходит в Telegram с кнопками публикации и скрытия, одновременно сохраняясь на модерации в Django Admin. В разделе «Zallar va xonalar» можно открыть/закрыть помещение, а владелец может добавить новое. Каждый callback повторно проверяет доступ сотрудника.

Если `/start` нажимает обычный посетитель без роли сотрудника, бот не раскрывает админские функции: он показывает название ресторана и две публичные кнопки — меню и бронирование.

Раздел «Arizalar tarixi» показывает сегодняшние, подтверждённые, ожидающие ответа, отклонённые, отменённые или все заявки. Список идёт от новых к старым по 15 записей на странице. Можно выбрать диапазон дат и скачать аккуратный Word-отчёт с данными клиента, датой визита, помещением, статусом, ответственным и причиной отказа. Чтобы файл быстро открывался в телефоне, одна выгрузка ограничена 500 самыми новыми заявками выбранного раздела.

Гость бронирует без аккаунта. После создания заявки защищённая ссылка статуса сохраняется только в браузере этого устройства и появляется в меню как «Oxirgi bron / Последняя бронь». Если гость очистит данные браузера или откроет другой телефон, автоматического восстановления нет. Telegram/SMS-уведомления клиенту без согласия и отдельного внешнего сервиса сайт не отправляет; для срочной связи менеджер использует оставленный телефон.

Форма защищена от повторного нажатия: кнопка блокируется сразу, а уникальный ключ отправки на уровне базы гарантирует, что повторный POST вернёт ту же бронь, а не создаст дубликат. Telegram-уведомление отправляется в фоне и не задерживает переход гостя на страницу статуса.

## Логика доступности

- слоты строятся из `WorkingHours`, а не зашиты в JavaScript;
- `RestaurantClosure` блокирует день или интервал;
- помещение фильтруется по `capacity_min`/`capacity_max` и флагам доступности;
- общий зал допускает параллельные заявки в пределах операционной модели;
- эксклюзивная комната не допускает пересечение подтверждённых броней;
- перед подтверждением и принятием предложенного времени доступность проверяется заново в транзакции;
- PostgreSQL использует advisory lock для пары «помещение + дата», защищая гонку между менеджерами;
- публичная страница открывается только по криптографически случайному UUID и не выводит телефон гостя.

## Проверка

```powershell
python manage.py check
python manage.py makemigrations --check --dry-run
python manage.py test -v 2
node tools/browser_check.js
```

Браузерная проверка использует установленный Chrome и bundled Playwright. Она проходит ширины 360, 375, 390, 430, 768, 1024 и 1440 px, проверяет горизонтальный overflow, меню, RU/UZ, карточку блюда, мобильную навигацию, трёхшаговое бронирование, preview, сохранение и защищённую status page. Скриншоты сохраняются в `artifacts/`.

## Railway: один Project, три Service

Создайте один Railway Project и подключите один GitHub-репозиторий к двум сервисам приложения и PostgreSQL.

### Service 1 — Beshbarmak Web

- Build: `pip install -r requirements.txt`
- Pre-deploy/Release: `python manage.py migrate && python manage.py collectstatic --noinput`
- Start: `gunicorn config.wsgi:application`
- Healthcheck: `/`

### Service 2 — Beshbarmak Telegram Bot

- Build: `pip install -r requirements.txt`
- Start: `python -m telegram_bot`

### Service 3 — PostgreSQL

Оба сервиса получают один и тот же `DATABASE_URL`. Для Web также задайте `SECRET_KEY`, `DEBUG=False`, `ALLOWED_HOSTS`, `SITE_URL`, `APP_TIMEZONE=Asia/Tashkent`. Для Bot добавьте `BOT_TOKEN` и `PRIMARY_OWNER_TELEGRAM_ID`.

Не запускайте web и polling-бот в одном Python-процессе.

Для загружаемых фото подключите Railway Volume к Web-сервису с mount path `/app/media` (если рабочая директория сервиса `/app`). Без volume локальное media-хранилище Railway эфемерно. Bot-сервис держите в одном экземпляре, чтобы не запускать два polling-процесса для одного токена.

## Основная структура

```text
config/                 settings, корневые URL, WSGI/ASGI
menu/                   существующее RU/UZ меню и RestaurantSettings
reservations/           модели, формы, services, web/staff views, Telegram notifications
telegram_bot/           отдельный aiogram 3 polling-процесс
templates/menu/         меню и информация о ресторане
templates/reservations/ клиентское бронирование и status page
templates/staff/        панель ресторана
static/                 CSS, JavaScript и изображения
tools/browser_check.js  сквозной адаптивный browser QA
```
